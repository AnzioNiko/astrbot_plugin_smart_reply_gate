# 更智能的回复

消息先经过事件筛选：机器人自身消息、已匹配的 AstrBot 官方唤醒流程和其他插件命令会跳过本插件的判断器。对于已匹配的其他插件命令，插件还会阻止 AstrBot 默认主模型把命令文本当成普通聊天再次回复，同时保留命令插件本身的处理。关键词/正则、开启判断的 @本机器人/引用机器人本人消息及跟进窗口消息按各自规则进入判断器。其他群聊消息只有在主动回复已启用、群白名单允许、概率抽中且冷却/能量检查通过后才调用判断器；未抽中或限频未通过时会跳过判断器并阻止本次默认主模型请求。判断器通过后才进入 AstrBot 主回复流程。

## 与 AstrBot 官方唤醒词的区别

本插件的关键词和正则在消息正文任意位置匹配，命中后进入普通 LLM 回复流程；是否经过回复判断由判断器总开关控制。它们不是 AstrBot 官方唤醒词，也不会作为工具指令使用。两类触发可以同时启用，任一命中即触发。对应列表留空即可关闭那一类规则。

默认情况下，群聊中 @ 本机器人或引用/回复机器人本人发送的消息会直接经过判断器，判断器可能拒绝回复。@ 通过机器人的 QQ 号识别；引用通过被引用消息的发送者 ID 识别。@ 其他群成员或引用他人消息不会被当作机器人定向消息，主动回复开启时仍先经过群白名单、随机抽样和限频。可通过“判断 @BOT 和引用BOT本人消息”单独关闭机器人定向消息的判断；命中关键词/正则时仍按明确触发规则判断，处于跟进窗口时仍由跟进窗口判断开关控制。

## 功能

- 在关键词列表中逐项添加关键词，消息包含任意一项即命中；列表留空时关闭关键词规则。
- 在正则列表中逐项添加规则，任一正则在消息任意位置匹配即命中；列表留空时关闭正则规则，无效正则记入日志并忽略。
- 从旧版升级时，插件会在加载时把原有的换行文本关键词和正则配置迁移成列表并保存。
- 私聊规则默认关闭。开启后，仅命中关键词或正则的私聊消息进入判断；未命中时阻止 AstrBot 默认回复。
- 判断器可选 AstrBot Provider 或 TypeSafe。AstrBot Provider 从已有 Provider 下拉选择；留空时沿用当前对话模型。TypeSafe 使用官方 SDK 和可选模型 ID（默认 `jev-latest`）；API Key 只从 AstrBot 进程环境变量 `TYPESAFE_API_KEY` 读取，不保存在插件设置中。
- 是否回复判断有独立总开关，默认开启。关键词/正则、启用判断的 @BOT/引用BOT本人消息和跟进窗口消息进入判断器；其他群消息（包括 @其他人或引用他人消息）须先通过主动回复白名单、概率抽样及冷却/能量检查。未抽中、群不在白名单或限频未通过时不会调用判断模型。AstrBot 官方唤醒、已匹配的其他插件命令和机器人自身消息跳过本插件。关闭总开关后，符合插件触发条件的消息绕过判断器并直接进入主回复流程。
- 判断器支持 Noul 二元判断和 Score 五级评分；TypeSafe Noul 默认阈值为 0.5，Score 默认最低 3 分。普通 AstrBot Provider 的 Noul 按模型返回的布尔值判断，不使用数值阈值。
- 可在设置中开启“调试：记录判断请求耗时”（默认关闭），查看每次判断模型请求从发出到收到响应的耗时；失败或超时也会记录已耗时。
- 可在设置中开启“调试：记录随机抽样结果”（默认关闭）。抽样命中与否默认不写常规日志；打开后会记录每次主动回复抽中或未抽中的结果。
- 判断请求提供当前消息、最近 5 条对话和当前会话使用的人格提示词。人格提示词帮助判断器识别机器人名称、自称和别名；如果用户是在称呼机器人并自然问候、提问、请求帮助或接话，会倾向于允许回复。
- 群聊主动回复独立开关，默认关闭。开启后，除关键词/正则、@BOT、引用BOT本人消息和跟进窗口外，其他群消息（包括 @其他人或引用他人消息）先通过群白名单和每条消息独立的概率抽样（默认 10%），抽中后再检查冷却/能量；这些前置条件都通过后才调用判断器。不抽中或限频未通过时不调用判断模型，并阻止本次默认主模型请求。白名单为空时所有群可参与；非空时仅名单内群参与。其他机器人账号不排除。
- 主动回复支持固定冷却和能量限频。默认固定冷却 300 秒；能量模式按群隔离，默认上限 100、成功消耗 30、每 30 秒恢复 1 点。普通消息先抽样，抽中后检查能量；默认达到 50 点才进入判断，门槛留空时跟随成功回复的能量消耗值。能量持久化，重启后按停机时间恢复。
- 同一发送者消息跟进有独立总开关，默认开启。插件回复或普通 @BOT 回复发送成功后，会为该群原发送者开启默认 30 秒跟进窗口。窗口内消息默认先经过“是否值得回复”判断；可单独关闭跟进判断，或通过判断总开关统一关闭判断。窗口不跨重启。关闭跟进总开关会清除已有窗口并停止创建和触发跟进。续聊刷新默认关闭；开启后收到续聊消息时立即刷新计时。
- 每次判断结果、限频跳过和错误回退都会记入 AstrBot 日志；主动抽样命中与否仅在抽样调试开关开启时记录。

## 判断失败时的处理

- 关键词/正则明确触发：判断器报错或超时会记录错误并放行主模型。
- 主动回复候选只有在抽样和限频检查通过后才会调用判断器；判断器报错或超时会记录错误并跳过本次回复。未抽中、冷却中或能量不足时不发送判断请求。
- 判断器总开关关闭时，所有插件触发分支直接放行主模型。
- 判断器报错时，关键词/正则、@BOT 和引用机器人本人消息按明确触发规则放行主模型；主动回复判断失败则跳过本次回复。AstrBot 官方唤醒及其他插件触发消息跳过本插件。跟进窗口的判断由跟进开关及判断总开关控制。
- 其他插件命令由对应命令插件处理；本插件识别到已匹配命令后会跳过判断器并阻止 AstrBot 默认主模型重复回复命令文本。

## 主动回复与 AstrBot 设置

插件的群聊主动回复有独立概率和限频配置，不会修改 AstrBot 自带的随机概率主动回复设置。如果两者同时开启，可能对同一消息重复回复；请按需要关闭其中一套。

## 配置界面说明

主动回复关闭时，概率、群白名单、抽样调试和限频设置会隐藏。判断器总开关关闭时，判断器模式、模型、阈值、判断说明、超时及请求耗时调试设置会隐藏。开启判断后，可单独设置是否判断 @BOT 和引用BOT本人消息；Provider 与 TypeSafe 设置按“判断器模式”显示，Noul/Score 阈值按对应选项显示。关闭“启用同一发送者消息跟进”后，跟进判断、时长和续聊刷新设置会隐藏。

## 配置 TypeSafe

1. **安装 SDK 依赖。** 插件的 `requirements.txt` 已固定 TypeSafe 官方 Python SDK 和包索引。先确认它安装在 AstrBot 实际使用的 Python 环境中；若 AstrBot 没有自动安装插件依赖，可在插件目录使用该 Python 执行：

   ```powershell
   python -m pip install -r requirements.txt
   ```

2. **设置 API Key 环境变量。** 在运行 AstrBot 的环境中新增 `TYPESAFE_API_KEY`，值填写 TypeSafe API Key。Windows 可在“环境变量”设置中添加用户变量；若 AstrBot 运行在服务或容器中，则要在对应的启动配置或容器环境中设置。仅在另一个终端里设置变量，不会自动传给已运行的 AstrBot。

3. **重启 AstrBot。** 环境变量只会在进程启动时传入；设置后重启，插件才能读取到它。密钥不会保存在插件配置中。

4. **选择判断器。** 在“更智能的回复”插件设置中开启判断器并将模式选为“TypeSafe”。模型 ID 可留空使用 `jev-latest`，也可填写其他受支持的 TypeSafe 模型 ID；随后选择 Noul 或 Score 并按需设置阈值。

若日志提示未设置 `TYPESAFE_API_KEY`，请检查变量是否配置在 AstrBot 实际运行的用户、服务或容器环境中，并再次重启。普通 AstrBot Provider 模式不需要此变量。更多 SDK 信息见 [TypeSafe 官方文档](https://core.elsaifoundry.ai/guides/typesafe.html)。

## 实现边界

插件在消息事件处理中对自己的触发分支先运行判断器，再通过 AstrBot 默认回复链路处理获准消息，以保留 AstrBot 当前会话和角色上下文。AstrBot 若为该会话配置了 Agent 工具，获准后的默认处理仍可能按 AstrBot 原配置调用工具。
